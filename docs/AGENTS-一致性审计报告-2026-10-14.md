## 二、真实模块图（来自构建脚本，非文档）

```
XinChat (rootProject)
├── build-logic/  (includeBuild, 独立构建)
│   └── convention/  → 7 个 Convention Plugin
├── app                                    [com.android.application]
├── core/
│   ├── designsystem   library + compose
│   ├── navigation     library + hilt + serialization
│   ├── data           library + hilt
│   ├── common         library + hilt
│   ├── util           library + serialization
│   ├── network        library + hilt
│   ├── model          library + serialization

│   ├── datastore      library + hilt + serialization
│   └── result         library + serialization
└── feature/
    ├── auth / chat / contact / main / user   [xinchat.android.feature]
```

**关键构建事实**

- `settings.gradle.kts` 中 `//include(":core:ui")` 被注释 → **`core:ui` 不存在**（`core/` 目录下亦无 `ui/`，`AndroidFeatureConventionPlugin` 中对应依赖同样被注释）
- `AndroidApplicationConventionPlugin` 与 `AndroidLibraryConventionPlugin` 均定义 `flavorDimensions += listOf("env")` + `dev` / `prod` 两个 flavor → **所有模块都有 flavor 维度**，这是 P0-03 的根因
- namespace 由 Convention Plugin 按 `feature/<x>` / `core/<x>` 路径正则自动生成（`AndroidLibraryConventionPlugin`），各模块 `build.gradle.kts` 里的 `namespace` 与之重复但一致
- `configureKotlinAndroid` 统一设置 `compileSdk` / `minSdk` / `JavaVersion.VERSION_11` / `JVM_11` / `buildConfig = true` / core library desugaring
- `AndroidLibraryConventionPlugin` 注入 dev/prod 的 `BASE_URL`，并强制 `prodBaseUrl` 以 `https://` 开头

**依赖边（仅列可疑方向）**

```
core:navigation → core:data          ← 契约层耦合数据层（P1-05）
core:util       → core:designsystem  ← 工具层反向依赖主题层（P1-06）
core:data       → core:database      ← database 为空壳（P0-05）
feature:main    → feature:contact / feature:chat / feature:user  ← 违反第 38 条（P0-09）
```

## 六、结论

**总体判定：工程实现质量良好，但"规范—代码"治理链路已断裂。**

三个层次的问题需要区分对待：

1. **治理层（P0-01、P0-02）是根因。** `AGENTS.md` 被 `.gitignore` 排除、`gradlew` 与 `gradle.properties` 同样未跟踪 —— 这使规范文档既无法共享也无法随代码演进，直接导致 P1-01 中"文档滞后 4 个月、模块清单错误"的结果。修复这两条的成本极低（改 `.gitignore`），但收益最大：它是其余所有漂移问题的结构性解药。

2. **门禁层（P0-03、P0-04）是当下可见的失败。** 文档第 135 行的测试命令照抄即失败；`lint` 有 3 个真实错误（`ProfileScreen.kt` 的 `context.getString` 回退文案在语言切换后不会更新）。这意味着"按 AGENTS.md 走一遍验证"当前会以失败告终。

3. **架构层（P0-05 ~ P0-10、P1-05 ~ P1-07）呈现清晰的模式：** 工程引入了 flavor、Convention Plugin、Navigation 3、多 core 模块等较成熟的基础设施，但**AGENTS.md 第 46–56 行与第 58–59 行规定的 Route/Screen 分离范式完全没有落地**（13/13 Screen 直连 ViewModel），`core:ui` 已被移除而文档未同步，Room 只有插件没有实现。即：**构建基础设施领先于文档，而文档领先于（或说脱离了）UI 层实际实现**。
